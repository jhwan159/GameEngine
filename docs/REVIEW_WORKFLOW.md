# 사용자 코드의 두 AI 검토 흐름

> 2026-11-05: CLion은 더 이상 사용하지 않는다. 아래 CLion 설치·설정과 Start-CLion.cmd 기록은 과거 환경 기록이며 Start-CLion.cmd는 삭제했다. 현재 IDE는 VS Code다.

## 역할

사용자가 소스를 작성한다. 현재 대화의 Codex는 개념 설명·과제 분할·검토 결과 통합·실제 검증을 맡는다. Claude는 같은 저장된 코드의 독립 검토를 맡는다. 코드 수정은 사용자가 수행하며, 전체 구현을 명시적으로 요청한 경우에만 AI가 구현한다.

## 모델

이 프로젝트의 Claude 기본 모델은 `.claude/settings.json`의 `claude-sonnet-5-5`다. 구조·객체 소유권·GPU 동기화·저장 형식 변경 등 심층 검토는 해당 호출에만 `ANTHROPIC_MODEL=claude-opus-5-5`를 적용한다. 계정이나 서버가 모델을 거부하면 실패를 보고하고 다른 모델로 몰래 바꾸지 않는다. Opus 경로는 실제 해당 호출의 결과를 확인하기 전까지 검증 완료라고 표시하지 않는다.

공식 모델 ID와 최소 CLI 버전은 [Claude Code 모델 설정](https://code.claude.com/docs/en/model-config)에서 확인한다. 2026-10-24에 설치된 CLI를 2.1.201에서 2.1.310으로 업데이트했다. 로그인 여부는 확인했고, 계정별 모델 사용 가능 여부는 실제 호출로 검증한다.

## 검토 요청과 실제 순서

1. 파일을 저장하고 현재 대화에서 “이번 과제 코드 둘이 검토해 줘”라고 요청한다. 파일 경로·의도한 동작·실행 결과를 함께 주면 좋다.
2. 조율자가 상태 보드와 P00 등 현재 단계 문서만 읽고 변경 파일 범위를 정한다.
3. 사용자 코드의 읽기 전용 검토 카드를 Codex 소유로 추가한다. runner의 `run`은 코드 구현이 아닌 **읽기 전용 점검**을 수행하며 변경 파일 목록은 빈 배열이어야 한다.
4. `review`가 Claude를 읽기 전용 도구로 호출한다. 일반 검토는 Sonnet 5.5, 심층 검토는 호출 한정 Opus 5.5다.
5. 두 검토를 비교해 위치·이유·힌트·확인 방법을 설명한다. 사용자가 수정하면 바뀐 내용으로 다시 검토한다.
6. 승인 후 실제 빌드·실행·필요한 테스트를 `verify`에 등록한다. 테스트를 실행하지 않은 채 완료 처리하지 않는다.
7. 짧은 결과·남은 문제·다음 과제를 상태 보드와 옵시디언 일지에 기록한다.

이 작업은 **과제 단위 요청 시 자동 호출** 방식이다. 파일 저장 감시나 상시 백그라운드 리뷰는 설치하지 않았다. 두 CLI의 사용량은 각각 소비된다.

## 초반 리뷰 기준

- 문법·정상 종료·출력 등 과제의 동작.
- 컴파일과 링크, 표준 C++ 사용.
- 초기화·오류 경로·객체 소유권·수명.
- Windows 전용 코드가 공통 코드에 들어갔는지.
- CMake 타깃의 C++20 요구와 두 OS의 빌드 재현성.
- IDE를 바꿔도 공통 CMake와 명령행으로 빌드할 수 있는지, 로컬 `.idea`나 CMakeUserPresets.json이 엔진·공개 SDK의 필수 의존성이 되지 않았는지.
- 지금 필요하지 않은 구조 때문에 학습 난도가 커지지 않았는지.

## 문서와 토큰 사용

파일 내용을 모델이 읽는 것도 입력 토큰을 사용한다. 소스 저장 위치가 옵시디언이라는 이유만으로 무료가 되지는 않는다. 전체 계획·전체 대화 대신 현재 단계·바뀐 파일·관련 테스트·미해결 사항만 전달해 입력을 줄인다. 캐시 할인이나 실제 금액 절감은 이 프로젝트에서 측정하지 않았다.

전체 코드가 작을 때는 통째로 읽어도 된다. 규모가 커지면 diff를 출발점으로 삼되 결함 판단에 필요한 호출부·타입·테스트까지 읽는다. 토큰 절약을 이유로 필수 문맥을 생략하지 않는다.

## 첫 개발 환경

Windows는 설치된 Visual Studio 2026의 MSVC 도구를 사용하며, 사용자가 선택한 IDE는 CLion이다. **CLion 2026.2.3 설치와 GUI의 MSVC·CMake·Ninja 연결을 완료했다.** 사용자가 첫 실행을 마친 뒤 조율자가 Visual Studio를 기본 툴체인으로 저장하고 경로를 확인했다. Start-CLion.cmd는 실행 파일을 확인하고 `Start-Dev.cmd --terminal`로 준비한 환경에서 기존 프로젝트 폴더를 여는 용도다. 엔진의 IDE 빌드·디버깅은 아직 검증하지 않았고 라이선스 상태를 검사·변경하지 않았다. 새 프로젝트 마법사로 소스나 CMakeLists.txt를 생성하지 않는다.

CMake 4.4.4와 Ninja 1.13.2를 사용자 범위로 설치했다. Start-Dev.cmd로 IDE와 별개의 개발자 터미널을 열 수 있다. 기존 VS Code 설정과 Engine MSVC x64 터미널 프로필은 선택 사항으로 보존한다. 임시 폴더의 C++20 프로그램으로 Windows Debug·Release 빌드와 CTest 실행을 확인했다. 이는 CLion이나 엔진 빌드 검증과 별개다. 엔진의 C++/CMake 파일은 아직 작성하지 않았다. 구체적인 사용법은 [개발 환경 안내](DEVELOPMENT_ENVIRONMENT.md)를 따른다.

공통 빌드 정의는 CMake이며 명령행 빌드를 유지할 계획이다. 다른 IDE는 각자의 CMake 연동·프로젝트 형식·플랫폼 지원에 맞춰 연결하며, 현재 모든 IDE에서 엔진을 검증한 것은 아니다. `.idea`와 CMakeUserPresets.json은 로컬 상태로 유지하고, IDE 설정을 엔진 실행이나 공개 SDK의 필수 의존성으로 만들지 않는다. 공유 CMakePresets.json은 해당 실습 때 다룬다.

Mac은 Xcode/Apple Clang + CMake + Ninja + Git, 네이티브 arm64 환경을 목표로 한다. Xcode는 Metal 실습에서도 필요하다. Mac 도구 설치·IDE 설정·빌드는 아직 확인하지 않았다. Windows와 Mac은 소스만 공유하고 build 디렉터리는 따로 만든다.

현재 첫 과제는 옵시디언의 “04 첫 실습 - 공통 C++ 빌드”다. EngineSandbox가 `Engine boot OK`를 출력하도록 두 파일을 직접 작성한다. 아직 엔진의 렌더러·씬·ECS를 만들 단계는 아니다.
